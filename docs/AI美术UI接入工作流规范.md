# AI 美术 / UI 接入工作流规范

适用项目：`御灵召来_城墙版`  
适用范围：AI 生成的 UI 视觉图、战斗界面美术、局内 HUD、布阵界面、强化卡、法阵、角色站位、按钮、血条、图标、装饰件等。

## 1. 核心原则

AI 生成的整张 UI 预览图，只能作为“视觉确认图”，不能直接作为工程资源接入。

工程接入必须遵循：

```text
视觉图确认
→ 工程标注
→ 资源拆分
→ 透明切图 / 九宫格 / 代码组件
→ 工程拼装
→ 实机截图叠图校验
→ 局部修正
```

后续所有新增美术资源，默认必须是带真实 Alpha 通道的独立 PNG/WebP 资源。禁止直接从整张预览图里截取一个矩形区域覆盖到游戏里。

## 2. 视觉图与工程资源的区别

### 2.1 视觉图

视觉图用于确认：

- 风格
- 构图
- 颜色
- 氛围
- 元素关系
- 大致尺寸比例

视觉图不是最终资源。视觉图里包含的按钮、文字、背景、角色、特效、装饰，不能默认直接裁切使用。

### 2.2 工程资源

工程资源必须满足：

- 资源本身用途明确
- 有透明通道或明确说明不需要透明
- 可以在不同状态、不同尺寸、不同分辨率下复用
- 与现有 UI 组件风格一致
- 不破坏原场景连续性
- 不包含不该入图的文字、箭头、选框、截图边缘、工具栏

## 3. 严禁事项

以下做法禁止作为正式接入方案：

- 从视觉图里截取一块矩形区域，直接盖到游戏画面上。
- 为了小改动重新生成整张界面。
- 新增法阵、光效、角色底座、UI 装饰时导出不透明背景图。
- 让 AI 重新设计已有按钮、血条、卡牌框，而不是复用现有组件。
- 视觉图确认后，不做资源拆分，直接进入代码实现。
- 接入完成后，只看“差不多”，不做实机截图对比。
- 把文字烘焙进本应由程序绘制的动态 UI。
- 把蓝色选框、批注箭头、标注文字、画布工具栏带进最终资源。

## 4. 标准接入流程

### 第一步：确认视觉图

目标是确认整体效果，不急着接工程。

确认项：

- 画面比例是否正确
- UI 层级是否清晰
- 角色/怪物/场景是否不互相抢视觉焦点
- 颜色与现有游戏是否统一
- 是否符合竖屏微信小游戏操作习惯

输出物：

- 已确认的视觉图
- 明确的修改意见
- 当前确认版本号或截图路径

### 第二步：工程标注

视觉图确认后，必须先做工程拆解标注。

标注内容包括：

- 每个组件的坐标、尺寸、锚点
- 组件层级：背景层、装饰层、角色层、特效层、HUD 层、文字层
- 文字是否程序绘制
- 哪些资源复用现有组件
- 哪些资源需要新增透明切图
- 哪些资源需要九宫格
- 哪些效果用代码绘制
- 不同屏幕比例下的适配规则

输出物：

- 资源拆分清单
- 接入坐标表
- 层级说明
- 交互状态说明

### 第三步：资源拆分

每个新增资源必须单独导出。

推荐分类：

| 类型 | 推荐形式 | 示例 |
|---|---|---|
| 背景 | 不透明整图 | 战斗场景、布阵背景 |
| 法阵 | 透明 PNG/WebP | 发光阵纹、阵位圈、主角底阵 |
| 装饰 | 透明 PNG/WebP | 角花、边框、灯、链条、符纸 |
| 面板 | 九宫格或透明 PNG/WebP | 弹窗、卡牌框、按钮底 |
| 动态文字 | 程序绘制 | 血量、波次、倒计时、伤害数字 |
| 动态条 | 程序绘制 + 框资源 | 血条、进度条、能量条 |
| 特效 | 代码绘制或透明序列帧 | 火焰、星针、圣光、震波 |
| 角色 | 透明 PNG/WebP | 御灵立绘、主角、怪物 |

新增资源命名建议：

```text
assets/art/ui/<界面>/<组件名>-v<版本>.png
assets/art/effects/<角色或技能>/<效果名>-v<版本>.png
assets/art/sprites/<角色>/<角色名>-v<版本>.png
```

示例：

```text
assets/art/ui/battle-lower/formation-blue-v5.png
assets/art/effects/suwen/star-needle-v1.png
assets/art/ui/upgrade-card/card-frame-common-v1.png
```

### 第四步：工程拼装

工程接入时，默认优先级如下：

```text
复用现有组件
→ 使用新增透明资源
→ 使用九宫格资源
→ 使用代码绘制动态部分
→ 最后才考虑新增整图资源
```

组件接入要求：

- UI 文字由程序绘制，除非是纯装饰性标题字。
- 血条、进度条、数字、倒计时必须保留动态能力。
- 按钮必须有可维护的点击区域。
- 状态变化必须可扩展：默认、选中、禁用、按下、可领取、冷却等。
- 同类按钮、面板、卡牌必须优先复用同一套组件。
- 不允许为了一个视觉效果破坏后续适配与维护。

### 第五步：实机截图校验

接入后必须产出游戏内截图，并与确认视觉图做对比。

检查项：

- 坐标是否偏移
- 比例是否一致
- 字体大小和字重是否接近
- 颜色、亮度、透明度是否一致
- 是否有矩形底、黑边、白边、拼接缝
- 场景是否连续
- 资源是否有真实透明通道
- 动态 UI 是否仍能正常变化
- 点击区域是否正确

如果有偏差，只修偏差，不重新生成整张界面。

## 5. 小改动流程

当需求是“小改动”时，默认禁止重做整图。

小改动包括：

- 改一个按钮位置
- 改文字内容
- 调整角色站位
- 调整法阵透明度
- 改血条宽度
- 调整某个 UI 组件尺寸
- 替换一个图标
- 局部增加光效

小改动标准流程：

```text
定位当前组件 / 资源 / 代码
→ 判断是否复用现有组件
→ 只修改目标资源或目标代码
→ 截图校验
→ 如有偏差继续局部修正
```

小改动时，给 AI 的推荐指令：

```text
这是局部修改，不要重新生成整张界面。
保留现有背景、布局、按钮、血条、字体和组件风格。
如需新增美术，只生成透明 PNG/WebP 资源。
如需改代码，只改对应组件、坐标或逻辑。
完成后用实机截图校验。
```

## 6. 新界面流程

当需求是“新界面”时，可以先生成整张视觉图，但不能直接接入。

新界面标准流程：

```text
1. 生成视觉图
2. 用户确认视觉图
3. 输出工程拆解方案
4. 生成独立透明资源 / 九宫格资源
5. 接入工程
6. 实机截图叠图校验
7. 局部修正
```

AI 在第 3 步必须输出：

- 资源清单
- 组件复用清单
- 新增资源清单
- 程序绘制清单
- 坐标和尺寸
- 层级顺序
- 适配策略
- 验收标准

## 7. 资源验收标准

### 7.1 透明资源

透明资源必须满足：

- 背景 Alpha 为 0
- 边缘无黑边、白边、灰边
- 不包含原场景矩形底
- 不包含视觉图里的其他组件
- 放到棋盘格背景上检查无脏边
- 放回游戏场景中检查无拼接痕迹

### 7.2 九宫格资源

九宫格资源必须满足：

- 四角不拉伸
- 边框可水平/垂直延展
- 中心区域可填充或透明
- 有明确切片边距
- 不把文字烘焙进背景

### 7.3 代码绘制资源

以下内容优先代码绘制：

- 血量数字
- 进度数字
- 波次文本
- 倒计时
- 伤害飘字
- 攻击范围圈
- 选中框
- 冷却遮罩
- 简单粒子
- 运行时状态高亮

代码绘制必须跟视觉图标注保持一致，包括字体、颜色、阴影、描边、对齐方式。

## 8. 组件复用规范

新增 UI 前必须先查现有组件。

优先复用：

- 现有按钮样式
- 现有血条样式
- 现有强化卡框
- 现有标题框
- 现有 HUD 控件
- 现有图标容器
- 现有字体与描边规则

如果确实需要新增组件，必须说明：

- 为什么现有组件不能复用
- 新组件会在哪些地方复用
- 是否需要状态变化
- 是否需要九宫格
- 是否需要后续扩展

## 9. AI 执行任务时的默认约束

后续 AI 接 UI / 美术任务时，默认遵守：

1. 不把视觉图当工程资源。
2. 不裁矩形图覆盖战斗场景。
3. 不为小改动重做整张界面。
4. 新增美术默认输出透明 PNG/WebP。
5. 动态 UI 默认用程序绘制。
6. 优先复用现有组件。
7. 接入前必须先拆资源清单。
8. 接入后必须截图校验。
9. 偏差修正只改偏差点。
10. 如果用户只是问方案，先回答方案，不擅自改工程。

## 10. 推荐任务模板

### 10.1 视觉图确认模板

```text
先只做视觉图，不接入工程。
目标是确认整体风格、布局和氛围。
不要输出切图，不要改代码。
```

### 10.2 工程拆解模板

```text
请基于已确认视觉图输出工程拆解方案。
需要列出：
1. 复用现有组件
2. 新增透明资源
3. 九宫格资源
4. 程序绘制内容
5. 坐标、尺寸、层级
6. 适配规则
7. 验收截图标准
```

### 10.3 资源生成模板

```text
只生成工程切图资源，不生成完整界面。
新增资源必须是透明 PNG/WebP。
不要包含背景、箭头、标注文字、选框、工具栏。
资源需要能独立放进游戏中拼装。
```

### 10.4 工程接入模板

```text
按已确认的资源清单和坐标接入工程。
优先复用现有 UI 组件。
不要使用整张截图裁切覆盖。
动态文字、血条、进度条用程序绘制。
接入后输出实机截图并与视觉图对比。
```

### 10.5 局部修改模板

```text
这是局部修改。
不要重新生成整张界面。
不要改变未提到的布局、组件、颜色和资源。
只修改目标组件或目标资源。
完成后做实机截图校验。
```

## 11. 当前项目特别规则

针对 `御灵召来_城墙版`，额外固定以下规则：

- 战斗下半部分的法阵、角色、灯、血条、主角必须分层处理。
- 法阵资源必须是透明图，不能截带背景的矩形图。
- 角色形象必须使用已经抠好的透明角色资源。
- 血条下方 UI 组件如果暂不接入，可以预留空白，不要用视觉图截图替代。
- 布阵界面与战斗界面的角色顺序必须一致。
- 预览页必须尽量直接调用正式战斗表现，避免维护两套逻辑。
- 强化、普攻、技能特效改动，优先在正式战斗逻辑中实现，再由预览页调取。

## 12. 接入完成定义

一个 UI / 美术需求只有满足以下条件，才算完成：

- 资源已按组件拆分
- 新增资源透明通道检查通过
- 工程已接入
- 动态 UI 仍可变化
- 实机截图已验证
- 与确认视觉图的主要偏差已处理或记录
- 没有矩形覆盖、拼接缝、脏边、错误文字、标注残留

如果只生成了视觉图，不能称为“已接入”。  
如果只接入了截图裁切，也不能称为“工程完成”。  
如果没有实机截图校验，只能称为“初步接入”。
